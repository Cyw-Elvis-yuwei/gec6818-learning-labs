# ADR-0002：板端以 LVGL 主线程和临时网络工作线程分离阻塞操作

- 状态：Accepted
- 日期：2026-07-23
- 范围：GEC6818 板端线程与页面生命周期

## 背景

TCP 连接、发送和接收可能因为服务器响应慢、网络断开或超时而阻塞。如果在 LVGL 事件回调中直接执行这些操作，触摸和界面刷新会被网络等待拖住；如果工作线程继续访问已经删除的页面，又会产生数据竞争或 use-after-free。

## 决策

- LVGL 主线程只处理触摸、页面、控件、定时器和结果展示。
- 每次业务网络请求由 `main.c` 创建一个临时 pthread；它消费稳定的请求参数副本，调用对应 client 并保存结果。
- 网络工作线程不调用任何 `lv_*` API，不持有页面控件的借用指针。
- 主线程发现请求结束后执行一次 `pthread_join()`，再检查当前页面是否仍有效，然后更新控件或切页。
- 离开排队页前删除 LVGL 自动刷新定时器；请求期间暂停刷新，完成后从完整周期重新计时。

这里的“两个线程”是职责模型：一个长期存在的 LVGL 主线程，加上请求期间临时存在的网络工作线程，不是两个永久网络线程。

## 结果

- 网络慢或断开时，LVGL 主线程仍可维持生命周期和界面状态。
- 页面删除前能够回收相关工作线程，避免旧线程访问新页面或已释放对象。
- 自动刷新复用既有 `get_current_ticket` 查询入口，不增加新的页面线程或推送协议。

## 未选择的方案

- 不在 LVGL 回调中同步 `connect`、`send`、`recv`。
- 不让后台线程直接更新标签、按钮或 screen。
- 不通过永久保留页面对象来掩盖线程生命周期问题。
