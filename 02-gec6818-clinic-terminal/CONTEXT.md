# 医路通领域上下文

更新时间：2026-07-23

本文件定义“医路通”项目在代码和文档中统一使用的业务词汇。它描述当前真实数据模型和稳定边界，不把未来预约、推送或医院管理系统的概念提前加入当前项目。

## 项目范围

医路通是运行在 GEC6818 上的联网医疗自助服务终端。普通用户通过板端完成注册、登录、科室查询、医生信息查询、按科室取号和排队状态查询；Ubuntu 服务器负责业务处理和数据库保存；管理员客户端负责选择科室并叫下一张等待号单。

当前系统模拟医疗服务流程，不提供诊断、处方、医疗建议或真实预约服务。

## 参与者

| 术语 | 含义 |
| --- | --- |
| 普通用户 | 在板端注册、登录、查询科室/医生、按科室取号并查看排队状态的人 |
| 管理员 | 在 Ubuntu 管理客户端选择科室并执行 `call_next` 的操作人员 |
| 板端 | GEC6818 上运行的 LVGL 终端程序，负责触摸、显示和发起请求 |
| 服务器 | Ubuntu 上运行的 Linux epoll TCP 服务，负责协议入口、业务规则和数据访问 |

## 核心业务词汇

### 用户（User）

用户由 `user_id` 唯一标识，账号信息保存在服务器端 `users` 表。登录成功后，服务器返回的 `user_id` 会贯穿主页、取号和当前号单查询；它不是 `request_id`，也不是 `ticket_id`。

### 科室（Department）

科室由 `department_id` 唯一标识，是当前取号业务的排队单位，也是医生筛选的条件。科室查询只展示科室，不创建号单。

### 医生（Doctor）

医生属于一个科室，包含姓名、职称和擅长方向。医生查询用于信息浏览和按科室筛选；当前取号不是指定医生预约，号单不绑定 `doctor_id`。

### 号单（Ticket）

号单表示用户在某科室某服务日期的一次排队事实，主要字段包括：

- `ticket_id`：数据库中的号单主键。
- `user_id`：取号用户。
- `department_id`：排队科室。
- `queue_number`：该科室当天展示给用户的排队号码。
- `status`：号单状态。
- `service_date`：号单所属服务日期。
- `created_time`：创建时间。
- `called_time`：被叫号时间，没有叫号时为空/零值语义。

### 号单状态

当前模型包含四种状态：

| 状态 | 含义 | 是否计入前方等待 |
| --- | --- | --- |
| `WAITING` | 已取号，等待叫号 | 是，前提是号码比本人小 |
| `CALLED` | 已被叫号 | 否 |
| `COMPLETED` | 服务完成 | 否 |
| `CANCELLED` | 号单取消 | 否 |

### 有效号单

在防重复取号规则中，“有效号单”指同一用户、同一科室、同一服务日期下处于 `WAITING` 或 `CALLED` 的号单。再次取号时返回原号单，不创建第二张有效号单。

### 当前叫号与前方等待人数

`get_current_ticket` 由服务器一次查询返回本人的号单和排队摘要：

- 当前叫号：同科室、同日期最近一次 `CALLED` 号单的 `queue_number`；没有时传输 `null`。
- 前方等待人数：同科室、同日期、号码小于本人且状态为 `WAITING` 的号单数量。
- 本人不是 `WAITING` 时，前方等待人数在业务上显示为无需等待。

板端只展示服务器计算的摘要，不在本地复制 SQL 或自行推算排队规则。

## 稳定业务规则

1. `create_ticket` 按科室取号，只使用 `user_id` 和 `department_id`，不使用 `doctor_id`。
2. 同一用户、同一科室、同一天不能重复持有两张 `WAITING`/`CALLED` 有效号单。
3. `call_next` 只从指定科室当天的 `WAITING` 号单中选择，排序为 `queue_number ASC`、`id ASC`。
4. 叫号成功后状态改为 `CALLED`，并写入服务器时间 `called_time`。
5. `get_current_ticket` 是板端查询本人号单、当前叫号和前方人数的统一入口。
6. 科室查询、医生查询和门诊取号是三个不同流程；查询页面不隐式创建号单。

## 技术边界词汇

| 术语 | 在本项目中的含义 |
| --- | --- |
| Handler | 服务器协议入口，负责 JSON 解码、字段校验、调用 Core 和响应编码 |
| Core | `clinic_core_handle()` 所在的业务层，负责请求分发、规则判断和错误映射 |
| Store | Core 使用的数据访问抽象，屏蔽具体数据库实现 |
| SQLite | 服务器端 Store 的具体持久化实现，开发板不直接访问 |
| epoll | Ubuntu 服务器统一监听多个 socket 连接的 Linux 事件机制 |
| 网络工作线程 | 板端为避免阻塞 LVGL 而临时创建的 pthread；只收发网络和保存结果 |
| LVGL 主线程 | 板端负责触摸、页面、定时器和控件更新的线程；网络线程不能调用 `lv_*` |
| 换行分帧 | TCP 字节流中以 `\n` 表示一条 JSON 消息结束，解决半包和粘包 |

## 不使用的术语

- “医生预约”不是当前号单语义；当前实现是按科室取号。
- “自动推送”不是当前刷新语义；当前排队页保留手动刷新，并已增加 5 秒自动查询。
- “开发板数据库”不是当前架构；SQLite 只部署在 Ubuntu 服务器端。
